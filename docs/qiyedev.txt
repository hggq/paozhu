## 模块优先级建议（开发顺序）

```
第一阶段（MVP）
├── HTTP 框架 + 路由
├── 数据库 ORM + 连接池
├── 用户认证（JWT）
├── RBAC 权限
├── 统一响应 + 参数校验
└── 日志系统

第二阶段（核心业务）
├── Excel 导入导出
├── HTML → PDF
├── 文件上传 / 对象存储
├── 操作日志 / 登录日志
├── 数据字典
└── 定时任务

第三阶段（增强）
├── 邮件 / 短信 / WebSocket
├── 消息队列 + 异步任务
├── 缓存（Redis）
├── 图片处理 / 二维码
├── 工作流 / 审批
└── 报表统计

第四阶段（运维）
├── 监控 + 告警
├── 限流熔断
├── 链路追踪
├── 灰度发布
└── 自动化部署（Docker / CI/CD）
```

## 总结

一个完整的企业后台，C++ 侧大约需要集成 **15～25 个第三方库**，自研 **10～20 个业务模块**。核心难点不在单个模块，而在于：

1. **统一异常处理**：所有模块的错误码、日志、回滚策略一致
2. **并发安全**：连接池、缓存、任务队列的线程/协程安全
3. **可配置化**：功能开关、参数热更新，避免改代码重新编译
4. **可观测性**：每个模块埋点，出问题能快速定位
